Cross-origin theft of Pinterest account data and MFA backup codes via JSONP on ask.pinterest.com

This page is served from a completely different website (akashsebastian.com) than the victim's Pinterest session. While you are logged in to Pinterest in this browser, this page silently reads your account email, profile, multi-factor backup codes and active session list — by loading ordinary <script> tags. No click, no prompt, no password. Open your DevTools network tab to watch the requests happen.

Every block above is a live response from Pinterest's servers, delivered into this foreign page's JavaScript. An attacker hosting this on any website could have logged all of it the moment you visited, while the page showed you anything at all — an article, a game, a loading spinner. Nothing about the Pinterest tab needs to be open.

Read-only demonstration against my own test account. No data was modified, no codes were used, and nothing was sent to any third party — every response is rendered locally in your browser. Root cause: ask.pinterest.com/api/proxy/pinterest/* reflects any callback parameter and returns access-control-allow-credentials: true with no origin allowlist, while Pinterest session cookies are SameSite=None. The www.pinterest.com resource relay does not honor callback — the JSONP behaviour is unique to the ask proxy.
