Cross-site account deactivation of a logged-in Pinterest user

One form POST, no CSRF token. probing…

While a Pinterest session is alive in this browser, a single cross-site form POST to the ask.pinterest.com proxy runs v3_deactivate_user and destroys the account. No password, no re-auth prompt, no Pinterest tab. The proxy forwards v3 writes with the user's SameSite=None session cookies and no CSRF layer — while Pinterest's own www resource layer requires a double-submit X-CSRFToken header and bounces plain form posts to /csrf_error/. The write channel is selected from step 1: hidden iframe when third-party cookies are attached (silent, the victim sees nothing), top-level navigation when they are blocked (Safari/ITP, Firefox strict, Brave, Chrome 3p-phaseout) — where the cookie rides on every browser and the final action lands the victim back on pinterest.com.

1Recon: confirm the victim session (JSONP read)

A script tag pointed at the proxy wraps the response in a callback, so this foreign page can read the account. Success selects the silent channel; failure selects the top-level one.

Root cause: ask.pinterest.com/api/proxy/* forwards v3 reads and writes with the user's SameSite=None session cookies and no CSRF layer at all. Fix: enforce the same X-CSRFToken double-submit header or an Origin allowlist on the proxy, or restrict the proxy to GET.
